Dear Gaby,

thanks to your intervention yesterday, we managed to find a few problems in the Bayesian mode and we found out why it only accepted 101 sets every time (and therefore not very good results). It had two reasons:
When calling the function to check significant change, the parameter for a number of identical sets was set to 50. We simply overlooked it previously. However, even after setting it to 500, it always ended after 1001 accepted sets. This brings us to the second reason…
In the end of every try (every iteration), we call function check_dataframe_significant_change (this is the one I mentioned in the previous point). This function drops NA values in the data frame of parameter sets. Then it calls the function check_significant_change. This function (it is the same as the one you sent us yesterday) actually checks the change.
- if there is fewer accepted sets than 2*"desired_number_of_identical_sets", it returns True
- else, it computes p-values in t-test and F-test, and compares the p-values with alpha. Here we found the mistake. There was this piece of code:
 significant_change = (p_val_avg > alpha) or (p_val_std > alpha)
If the condition is True, the function returns True. If it is False, it returns False.
However, the two portions of the sets are significantly different if the p-value is smaller, not larger than alpha. This means, it always stopped after meeting the first condition (the number of accepted sets), as it ended completely when the second condition was met, ie. when there was a significant difference. However, we want it to run further if there is still a significant difference between the last and the previous 500 sets, and stop just when there is no significance difference. Therefore, we changed it to:
 significant_change = (p_val_avg < alpha) or (p_val_std < alpha)
(Additionally, we find the two functions a bit confusing, as the outer function always reverts the boolean value from the inner function and returns it to the main code. We are thinking of merging these two into one. Is there any particular reason why there are two?)

After these changes, it didn't stop after meeting the length requirement (1001, previously 101). However, it still didn't converge. I ran it for the default 10,000 tries. Then, I tried 30,000 tries and still nothing. Maybe it's the problem of the min and max bounds? We created the histograms and there are a few parameters that are inclined to one of the bounds.
